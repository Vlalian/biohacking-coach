# Coach-Evaluation MVP Route

Label: wayfinder:map
Status: charting — destination named 2026-07-16
Created: 2026-07-16

## Destination

A single, decided implementation route to a **hosted web-login eval-MVP**: Mads as the sole real athlete (his real Garmin data) plus an optional synthetic roster, with **both athlete and Head-Coach roles logging into a shared hosted backend**, the Coached Mode surface (per [ADR 0003](../../docs/adr/0003-coached-mode-authority.md), MVP-scoped), Tier-1 security hardening, and a right-sized consent/GDPR posture — such that the recruited human coach can evaluate the *real experience* with real data. The map is done when the architecture, stack, data model, feature scope, security, and GDPR decisions are locked and expressed as an ordered set of PRDs/issues a build session can pick up. **Plan-only**: this map decides the route; building happens in the feature issues afterward.

- [06 `display_name` vs identity separation](issues/06-display-name-vs-identity-separation.md) — **the name moves behind the `user_id` seam.** `athlete.display_name` → **`synthetic_label`**, nullable, set only for athlete rows with **no user** — real athletes' names come from better-auth via `user_id`; `coach.display_name` dropped (a coach always has a login, so it was pure duplication). Every name left in the training tables is now fabricated, so [ADR 0006](../../docs/adr/0006-server-authoritative-architecture.md)'s "a leak of the training data alone names no one" is true *as written* rather than weakened to "unless the athlete chose to be named" — chosen over amending the ADR or seeding a handle because it makes the promise structural, not conventional. Cost: a join to render a real name. ADR 0006 clarified (no amendment — the clause was right, the schema had drifted); [05](issues/05-server-data-model.md) amended in place. The **GDPR posture** item can now describe a leak honestly: opaque IDs, fabricated labels, no real name.
- [07 Schema names vs the glossary](issues/07-schema-names-vs-glossary.md) — **full glossary alignment**, not just the one name that lied: `weekly_session_count` → `training_sessions_per_week` (a **Weekly Session** is the ritual — the old name claimed to count those, and the answer is always one), `phase` → `training_phase`, `comm_style` → `communication_style`, `info_layout` → `information_view_layout` (also on `coach`). Went past the narrower recommendation on the argument that carried it: *"unambiguous in context" is exactly what a cold agent lacks*, and the glossary rule stops being a rule the moment the schema gets a standing exemption. `experience_level`, `race_target`, `equipment`, `profile` were already canonical. [05](issues/05-server-data-model.md) amended in place.
- **Both land in [slice 02](../eval-mvp-build/issues/02-login-with-better-auth.md)**, not a schema slice (the PRD forbids horizontal ones) — it is where `user` arrives, so a real name finally has somewhere to live, and where its own "no training table carries a name or email column" criterion stops being false in the code. Corrected on the way: the research sheet's "30-day retention window" overstated the exposure (it is a deletion *ceiling*; content is not retained by default), and `gdpr-decisions.md` decisions 5, 6 and C were factually wrong and are rewritten.
