# Triage

Move issues on the project issue tracker through a small state machine of triage roles.

Issue tracker: local markdown files in `.scratch/`. Every comment/update appended under `## Comments` heading.

Every comment or issue posted during triage **must** start with: `> *This was generated by AI during triage.*`

## Roles

**Category:** `bug` | `enhancement`

**State:**
- `needs-triage` — maintainer needs to evaluate
- `needs-info` — waiting on reporter
- `ready-for-agent` — fully specified, ready for AFK agent
- `ready-for-human` — needs human implementation
- `wontfix` — will not be actioned

Every triaged issue carries exactly one category role and one state role.

## Invocation

The maintainer describes what they want in natural language:
- "Show me anything that needs my attention"
- "Let's look at `.scratch/my-feature/issues/01-thing.md`"
- "Move this to ready-for-agent"
- "What's ready for agents to pick up?"

## Show what needs attention

Query `.scratch/` and present three buckets, oldest first:
1. **Unlabeled** — no Status line
2. **`needs-triage`** — evaluation in progress
3. **`needs-info` with recent activity** — needs re-evaluation

## Triage a specific issue

1. **Gather context.** Read the full issue file. Explore the codebase using domain glossary. Check `.out-of-scope/*.md` for prior rejections.
2. **Recommend.** Tell the maintainer your category and state recommendation with reasoning. Wait for direction.
3. **Reproduce (bugs only).** Trace the relevant code, run tests. Report: successful repro, failed repro, or insufficient detail.
4. **Grill (if needed).** Run `/grill-with-docs` if the issue needs fleshing out.
5. **Apply the outcome:**
   - `ready-for-agent` — post an agent brief (see `.agents/skills/triage/AGENT-BRIEF.md` for template)
   - `ready-for-human` — same as agent brief, but note why it can't be delegated
   - `needs-info` — post triage notes (template below)
   - `wontfix` (enhancement) — write to `.out-of-scope/`, link from comment

## Agent brief format (condensed)

```markdown
## Agent Brief

**Category:** bug / enhancement
**Summary:** one-line description

**Current behavior:** what happens now

**Desired behavior:** what should happen after the work

**Key interfaces:**
- TypeName / functionName — what needs to change

**Acceptance criteria:**
- [ ] Specific, testable criterion

**Out of scope:**
- Things that should NOT be changed
```

Do: describe interfaces and behavioral contracts. Don't: reference file paths or line numbers (they go stale).

## Needs-info template

```markdown
## Triage Notes

> *This was generated by AI during triage.*

**What we've established so far:**
- point 1

**What we still need from you:**
- specific question 1
```
